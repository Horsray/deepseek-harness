# @deepseek-ai/dsh-experimental-agnes-media

## Summary

Adds `generate_image` and `generate_video` so a model can create images and asynchronous videos without leaving the Session. The tools call the Agnes domestic API, commit each result as a durable attachment, and write the file into the Session working directory. The credential is never part of this package: the plugin reads the plugin `apiKey` config, `AGNES_API_KEY`, or `~/.dsh/agnes-api-key`.

<a id="use-this-package"></a>
## Use this package

Provide a credential before the first call, then ask the model for an image or a video.

```sh
mkdir -p ~/.dsh && printf '%s\n' "$YOUR_KEY" > ~/.dsh/agnes-api-key && chmod 600 ~/.dsh/agnes-api-key
```

`generate_image({ prompt, size?, ratio?, image?, output_path? })` performs text-to-image, single-image editing, or multi-image composition. `size` is a tier (`1K`–`4K`), `ratio` fixes the aspect, and `image` accepts public URLs or Data URIs.

`generate_video({ prompt, seconds?, aspect_ratio?, seed?, output_path? })` creates a `text`-mode task, polls until it settles, and downloads the MP4. The call can run for minutes, so it declares a cooperative timeout and forwards cancellation.

Both tools return the canonical `path`, `bytes`, and attachment id, and render the saved media for the model. Files land in the Session working directory unless `output_path` names another location.

<a id="understand-the-implementation"></a>
## Understand the implementation

The plugin registers both tools on the `tools` service and uses `workingDirectory` to resolve output paths and `attachments` to commit the bytes. `baseUrl` defaults to `https://api.agnes-ai.cn`; the international deployment uses `https://apihub.agnes-ai.com` with `agnes-image-2.0-flash`, so set `baseUrl` and the model separately when targeting it.

Video generation is asynchronous: `POST /v1/videos` returns a `video_id`, and `GET /agnesapi?video_id=…&model_name=agnes-video-2.5-flash` is polled until `status` reports `completed` or `failed`. Only the top-level `status`, `progress`, and `url` fields are authoritative.

<a id="model-experience"></a>
## Model Experience

The model sees two tool schemas with enum-constrained sizes, ratios, and durations, so invalid values are rejected before any request. Success returns a short JSON envelope plus the media itself; a failure returns the Agnes `code` and message, including `video_queue_full`, so the model can retry later instead of guessing.

Generated bytes never enter the transcript as base64: the result carries an attachment reference and a filesystem path.

<a id="known-limitations-and-deferred-work"></a>
## Known Limitations and Deferred Work

- Video generation only covers `mode: "text"`. Keyframe (`first_frame`/`last_frame`) and reference (`images`/`audios`) modes are not exposed yet.
- The video queue is shared upstream; a `503 video_queue_full` response is reported as a retryable failure and no local workaround exists.
- The plugin is not registered in the repository TypeScript aggregates or the tool catalog yet.
